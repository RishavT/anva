## v3 Section 30 review

### Product and Anva quality

Contracts separate policy, context, evidence, findings, evaluator messages, and proposals.
Findings and context require sources, inferred values are explicit, limitations are first-class,
and no model output can directly mutate accepted knowledge. Assurance is head-commit pinned and
a newer head marks active older work stale.

### Code and tests

Domain operations live in typed service modules rather than adapters. Transactions, row locks,
optimistic revisions, database checks, same-tenant foreign keys, immutable triggers, and
idempotency constraints protect critical invariants. Compose runs formatting, lint, strict mypy,
migration drift, contract drift, all tests, and coverage.

### Security, documentation, and evidence

Actor context carries tenant, authorization path, request correlation, and hashed IP metadata.
The generated HTTP skeleton requires bearer authentication, correlation IDs, idempotency keys,
and structured errors. ADR-012, ADR-016, and ADR-020 record artifact, dispatch, and tenant
decisions. No credentials enter job or contract examples.

## Findings fixed during self-review

1. A nested evaluator-result schema initially resolved a finding's source reference at the wrong
   JSON Pointer. Promoted the shared definition and added catalog validation.
2. Initial outbox transition keys used only revision, which collided when claim and retry shared
   an attempt number. Keys now include source and destination states.
3. Transition wrappers initially mutated terminal metadata before detecting an idempotent repeat.
   Repeats now return without unsaved in-memory changes.
4. Application tenant checks alone could not stop direct cross-tenant foreign keys. Added
   PostgreSQL composite constraints and forced-constraint integration tests.
5. ORM artifact immutability could be bypassed by bulk update. Added PostgreSQL update/delete
   triggers for artifacts and audit events.
6. A worker crash on its final leased attempt could leave a job permanently running. Claim sweeps
   now retain it as a terminal failure with an explicit error code and audit/outbox event.
7. The first OpenAPI skeleton described authorization as future work. It now declares global bearer
   authentication, mutation idempotency and correlation headers, and structured error responses.
8. The first full Compose gate found two strict-mypy inference failures in heterogeneous OpenAPI
   response dictionaries and one subsequent format drift. Typed response maps and formatting fixed
   both before the final run.

## Known limitations

- OpenAPI and MCP are generated contract skeletons; authenticated evaluator/proposal endpoints and
  the MCP protocol server are later issues.
- The outbox table and queue primitives are durable, but a production dispatcher, handler registry,
  lease renewal, metrics, and dead-letter operations are later worker slices.
- Version 1.0 is the first schema set, so there is no previous stable version to retain yet.
- Policy persistence and full assertion revision tables are later domain-model work; this slice
  stores policy version pins and immutable audit history.
- Database row-level security is not enabled; explicit service authorization plus composite
  constraints are the current defense-in-depth boundary.
