## What is included

- Compose-first installation, terminal-only ephemeral demo, upgrade, rollback,
  atomic-generation backup, failure-safe restore, migration rehearsal, and
  scoped uninstall procedures.
- A Python wheel, Codex and Claude skill archives, an install bundle, SPDX and
  CycloneDX image SBOMs, image/source security reports, vulnerability
  dispositions, release manifest, notes, and checksum closure: 13 public assets.
- Database-backed rate limits shared by API and MCP processes; correlated JSON
  request logs, W3C trace identifiers, authenticated metrics, and dependency
  readiness checks.
- Auditable retention and access-revoking organization decommissioning with the
  retained-data and legal-erasure limitations stated below.
- Standard GitHub build-provenance attestations and supplemental immutable
  product-source attestations for the downloadable assets and OCI digest.

## Install and verify

Consumers should download all assets, verify `SHA256SUMS`, verify both standard
and product-source attestations, read the digest from `release-manifest.json`,
and deploy that digest rather than the mutable version tag. Exact commands are
in the [install/upgrade/uninstall runbook](../runbooks/install-upgrade-uninstall.md).

The publication workflow verified a fresh bundle install without rebuilding the
image, migrations, readiness, and synthetic demo seeding against the immutable
digest. That technical lifecycle result is not the human-owned operator exercise
tracked by #44.

## Security and operating boundary

- The exact published image scan contains the approved 13-CVE/16-package-tuple
  no-fix set. Rishav Thakker's decision applies only to `v0.1.0`, product source
  `d919...`, the published image digest above, and the unchanged controls through
  2026-09-25. Drift, a recorded fix, or expiry requires remediation or a fresh
  decision; this is not a zero-high/critical claim.
- Production deployments must supply unique secrets, TLS termination, exact
  trusted-proxy addresses, metrics authentication, backups, and deployment-owned
  monitoring. Persistent aggregation, dashboards, alert delivery, and complete
  distributed tracing are not included.
- Decommissioning revokes access but is **not verified hard deletion or legal
  erasure**. Governed identity, audit, provenance, evidence metadata,
  source-derived rows, database artifact payloads, and object-store bytes may be
  retained.
- The product has no post-setup login/reauthentication flow. Organization
  decommissioning requires the setup-authenticated session to be no more than 15
  minutes old and otherwise fails closed.
- Chromium is the browser acceptance target. Other engines are unverified.
- External object-store and deployment-sized recovery, managed-deployment
  security/operations, durable observability, supported session re-entry, and
  deterministic Canvas 300-node p95 performance remain separately tracked
  post-MVP work.

attestation, or Actions record. Issue

custom attestations. The original attestations are retained.

This maintenance does not create `v0.1.1`, move `v0.1.0`, rebuild or push the
image, alter runtime bytes, renew risk acceptance, or close #43/#44.
