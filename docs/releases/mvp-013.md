## Installation boundary

The one-command source-checkout demo installation is:

```sh
make install-demo
```

It builds the current checkout, starts dependencies and application processes,
runs migrations, and idempotently seeds synthetic demo data. The demo service
prints its fresh token only to the attached terminal, disables Docker logging,
and is removed after the run. The exact local candidate produced a checksummed
wheel, skills, image, scans, SBOMs, manifest, and evidence archive, but this is
not proof of an immutable published-image install. `compose.release.yaml` is a local
artifact-builder/scanner overlay, not a published deployment bundle. No
published-image command may be advertised until an exact registry digest,
signed or provenance-attested source identity, and verified deployment bundle
exist. See the [install and uninstall
runbook](../runbooks/install-upgrade-uninstall.md).

## Data lifecycle boundary

The retention HTTP operation uses server time and expires evidence only when its
explicit expiration and the organization's minimum-retention cutoff have both
passed. It appends retention events and removes only the same organization's
expired operational rate-limit buckets. It retains governed history. The
organization-decommission operation requires the setup-authenticated human web
session to be no more than 15 minutes old, plus CSRF validation, exact slug
confirmation, and exact `DECOMMISSION <slug>` acknowledgement; bearer tokens and
the CLI are rejected. The current product has no post-setup reauthentication
flow, so an operator outside that 15-minute window cannot decommission an
organization until such a flow exists. When the precondition is met, the
operation revokes sources, tokens, scopes, memberships, service identities, and
repositories, then marks the organization decommissioned.

Decommissioning is an access-revocation operation, **not a verified hard-delete
or legal erasure operation**. It currently retains organization identity,
audit, provenance, immutable evidence metadata, source-derived rows, database
artifact payloads, and any object-store bytes. No documentation may describe
it as complete deletion until the deletion matrix and clean-data proof pass.

## Known limitations

- Local wheel, skill archives, image SBOMs, vulnerability output, source scan,
  exact-source evidence archive, release manifest, and `SHA256SUMS` are bound to
  clean source commit `94231d7e...` and local runtime image ID `c6ae3a8a...`.
  They remain unpublished local artifacts. No release tag, registry digest,
  signature/provenance, package/image publication, or GitHub Actions record
  exists.
- Backups now use unique generations and atomically replace a `current` pointer
  only after paired verification. Backup quiesces/resumes only the Anva writers
  that were running; a failed restore leaves them stopped. Migration rehearsal
  restores the database into a guarded disposable project and never reverses
  the live database. The exact-candidate drills passed inactive partial-generation
  pointer preservation, failed-restore stop, successful restore/resume, and
  disposable reversal/forward cleanup. The object drill covers Compose-managed MinIO, not an external object
  store. This is not proof that an older application binary can run against the
  new schema, nor proof of point-in-time or large-dataset recovery.
- Decommission's recent-authentication gate currently relies on the timestamp
  set by one-time product setup. No login or post-setup reauthentication flow is
  provided, so decommission becomes unavailable once that session is more than
  15 minutes old. This is an unresolved release limitation, not an alternative
  operator procedure.
- Production settings reject `ANVA_ENV=production` with debug enabled and
  require non-sample secrets plus a metrics token. TLS termination and exact
  trusted-proxy IP configuration remain deployment-owned. The Anva application
  containers carry the declared runtime hardening; this is not a blanket claim
  about every third-party service container.
- Release closure rejects tracked or untracked worktree changes and a mismatch
  between clean `HEAD` and the image OCI revision. Skills are rebuilt and
  verified. The source gate scans vulnerability, secret, and misconfiguration
  findings while excluding operator-owned directories from distributable
  output. The image gate has 14 reviewed no-vendor-fix exceptions expiring
  2026-08-18; it is not a zero-high/critical claim.
- Operational metrics are per-process counters. Persistence,
  aggregation, dashboards, alert delivery, and distributed trace export are
  not implemented or release evidence. W3C trace context and correlated JSON
  logs are provided; full cross-service spans are not.
- The application has no accepted byte/archive evidence-upload boundary. JSON
  evidence metadata remains inert; TST-007 upload scenarios still require
  product-level closure.
- Exact-repository bearer tokens are used for MCP. OAuth and enterprise SSO are
  not implemented.
- External model inference is not part of this release boundary. Model
  processing must remain disabled unless separately designed and approved.
- Chromium is the browser acceptance target. Other browser engines are
  unverified.
- Exact read-only `anva-test` corpus ingestion passed at commit `a66787b0...`.
  Its full non-browser/browser baselines and all 31 isolated assurance-oracle
  scenarios, sealed fresh-agent Codex/Claude executions, and human
  operator/user/developer acceptance are not current release evidence.
- Exact-candidate validation kept task-owned Docker resources below 5 GB using exact
  Compose-project, image, and cache cleanup. No Docker engine-wide 5 GB quota is
  implemented or claimed, and unrelated Docker resources must not be pruned.
- This work does not add, enable, or modify a GitHub Actions workflow, publish an
  image/package, create a tag, or create a public release.
- Production Terraform, billing, commercial quotas, customer support tooling,
  and an external penetration test are deferred as recorded in the
  [requirement matrix](requirements-evidence-matrix.md).
