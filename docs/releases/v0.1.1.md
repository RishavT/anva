# Anva 0.1.1

Status: release candidate preparation. No `v0.1.1` tag, image, or GitHub
Release exists until a separately authorized protected-environment run succeeds.

This patch release makes the supported decommission cleanup retry from #73 and
the synthetic operator drill harness from #80 available from the same immutable
product source. The release dispatch accepts only `v0.1.1` and requires the full
candidate commit; the existing tag, checked-out source, image revision,
downloadable assets, source predicates, and published digest must all bind to
that commit.

The #80 harness verifies the automation surface and records whether the
decommission CLI is present in that exact product image. It does not perform,
approve, or finalize the separate human #44 operator acceptance drill.

Publication remains blocked while the proposal job builds and attests a fresh
Trivy proposal for the exact v0.1.1 commit and image digest. RishavT must inspect
that artifact, its exact attested Trivy JSON report and database metadata, and
personally approve the exact pending GitHub `release` environment deployment.
The publishing job verifies GitHub's exact-run approval history, retained
evidence bytes, rebuild equality, proposal SHA, runtime controls, and expiry, then
attests the bound decision before publication. The v0.1.0 vulnerability
exception is historical evidence and is invalid for this candidate.

Rollback means redeploying the previously verified immutable v0.1.0 digest only
after confirming schema compatibility or restoring a verified backup. Tags,
release assets, attestations, and image digests are never moved or overwritten.
